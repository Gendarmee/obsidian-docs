API Gateway - важнейший архитектурный паттерн для построения сложных, устойчивых и расширяемых систем. Паттерн предлагает создание единого шлюза для общения клиента с нашей системой, что решает целый ряд проблем. Можно представить, что API Gateway будет той самой границей, которую, пересекая, пользователь попадает в наше приложение. Так же стоит отметить, что в каком-то смысле является реализацией паттерна [[Фасад]], но примененный к распределенный системе.

Зачастую нашему клиенту нужно обращаться к большому количеству сервисов, к примеру при покупке ему нужны данные о продукте, о наличии товара на складе, стоимости, сроках доставки и т.п. В технических реалиях, это представляет собой большое количество микросервисов - тут же сразу возникает множество скрытых проблем. А именно пользователю видна структура наших микросервисов и данные о них, такие как порт, ip, где находится - что делает нашу систему более уязвимой для атак, расширяет поверхность атаки на каждый микросервис. Требуется подход, который бы сильно упростил взаимодействие клиента с нашей системой. 

Этим подходом и будет API Gateway, то есть создание централизованного шлюза для входа в наше приложение. По сути он будет выступать как обратный прокси сервер, маршрутизируя запросы от клиента к микросервисам.
